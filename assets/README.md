## Refresh behavior

`.github/workflows/koi.yml` runs daily at 00:20 UTC, on manual dispatch, and when its workflow file changes. It uses only the built-in `GITHUB_TOKEN`, with `contents: write` confined to the publishing job. All actions are pinned to reviewed commit SHAs.

The generator writes to a temporary directory. Both images must pass format and dimension checks before replacing the committed output. A failed run leaves the last good assets in the repository. The commit step stages only the two koi images, skips unchanged output, and uses an ordinary push after rebasing onto `main`.

The README offers a PNG for reduced-motion browsers where supported, plus an explicit still-image link. No essential profile information depends on animation.

GitHub can pause scheduled workflows in public repositories after 60 days without activity. The last generated assets remain visible; re-enable the workflow in Actions if needed.
